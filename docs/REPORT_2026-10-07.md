# PiCC report, 2026-10-07: the v20 batch

For the project owner. Twenty-one two-hour runs, 2026-10-04 22:31 to 10-06
19:03 UTC, on the two newer tasks — SQL engine and chapters 1-18 compiler —
with Rust, Python and typed Python three times each, plus Rust under a
minimal specification three times (SQL only). The one change from v19: after
every round the harness tells the agent what its own build-and-example check
found. Scores from `analysis/v20_results.py` over the study summaries; what
each agent was told is in its run's `artifacts/rounds.jsonl` (`message`).

## 1. Summary

- **The harness held**: 21 of 21 runs used their full two hours, no reply
  lost to a server error, no conversation summary failed.
- **No run was lost to the output contract.** v17–v19 had lost eleven of
  forty runs to mistakes the agent could not see. In v20 every run that
  started wrong was told what the official build or the specification's
  example gave, and every one of them fixed it before the end — except one.
- **The one zero is a real failure**: `c18-rust-r2` wrote 6,000 lines of
  Rust before building, never had a compiling snapshot, and was told twice
  (and saw it itself eight times). That is the agent, not the setup.
- **Typing: no effect**, for the sixth batch running. Paired medians −0.011
  (SQL) and +0.004 (compiler), inside ±0.13.
- **The minimal specification** cost −0.432, −0.029 and −0.044 against the
  full one (median −0.044, inside ±0.13), but its three runs spread from 0.137
  to 0.778, and all three needed the check to learn the output format — two
  only in the last half hour. The full specification's runs had it right by
  round 1 or 2, nine of nine.
- Best scores so far on both tasks: SQL 0.875 (`python-r2`; the task's
  ceiling is 0.875 because one hidden script beats every engine), compiler
  0.681 (`python-typed-r3`; v19's best 0.670, v10's 0.501).

## 2. What the agent now sees

After each round, instead of `Continue.`, one of three messages (exact
wording in `scripts/run_experiment.py:round_check_message`):

- the build command failed → the command and its output (cargo's errors,
  `mypy`'s errors, a Python syntax error);
- built, but the specification's example gives a different output → what the
  program printed next to what is required, and the first line that differs
  (compiler: what each of the two example programs did);
- both pass → one line saying so.

It uses only what the specification already states. No test, score, hint or
round number reaches the agent. A trial run before the batch showed the
message arriving as composed and found one wording defect (a mid-edit
snapshot that did not parse was called "what the specification forbids"),
fixed before the first main run.

## 4. The low scores

- `c18-rust-r2`, 0: never compiled. 6,018 lines in 156 replies (the other
  runs: 270–490 replies), the official build run by the agent itself eight
  times, 64 then 54 errors. The deadline rule in the specification ("keep the
  program building at all times") and two harness messages did not change
  its approach.
- `sql-rust-r3`, 0.181: handles 1,000 statements in 0.2 s, then hangs for
  more than the 120-second limit on three large scripts; the scorer stops
  after three timeouts in a row. An engine bug on some construct; it also
  left debug prints on standard error.
- `sql-rust-minimal-spec-r3`, 0.137 and `-r1`, 0.417: thin engines that
  reached the output format only on the last snapshot.

None of these is a contract or harness zero.

## 5. Typing

Typed Python minus Python, paired by replicate, hidden score:

- SQL: +0.082, −0.013, −0.011 → median **−0.011**
- compiler: −0.055, +0.005, +0.061 → median **+0.004**

No effect detected (±0.13). The typed arm was the tightest on SQL
(0.794–0.861) and, with one more valid program count of 58, holds the best
compiler score; it also had the batch's slowest start to a passing check
(`typed-r3`, two rounds of `mypy` errors). Six batches (v4, v7, v10, v17,
v19, v20) have asked this question at n = 3–4 and none has found an effect.

## 6. Full specification against minimal

Rust-minimal-spec minus Rust, paired: −0.432, −0.029, −0.044 → median
**−0.044**, no effect by the ±0.13 line. But the arm is wide (0.137–0.778
against 0.181–0.849), and the mechanism is visible in the messages: each of
the three minimal-spec agents printed the example wrongly after round 0 and
learned the format from the check, two of them only in the last round. With
the check in place the minimal specification costs mostly time; without it
(v19, one run) it was −0.222. The check's presence is a known part of this
comparison, stated in the plan before the runs.

## 7. What this batch does and does not show

- Shows: telling the agent the result of the official build and the
  specification's example removes the contract zeros that dominated v17–v19,
  at no cost to the agent's time; the remaining low scores are program
  faults; typed Python and Python are within each other's spread on both
  tasks; the minimal specification's cost is mostly time to find the format,
  with wide variance.
- Does not show: an effect of typing in either direction; a reliable size
  for the specification effect (n = 3, spread 0.64); anything about the
  languages beyond three replicates.

## 8. Problems in the setup, this round

- The machine sat idle 1 h 49 min between v19 and v20 (the manifest swap was
  mine to do and my session was unavailable); the launcher refused to start
  rather than run the wrong manifests.
- The specification states no per-script time limit; `sql-rust-r3`'s engine
  hung rather than ran slowly, so this did not decide a score here, but an
  engine that is merely slow would be penalized without knowing. Worth one
  sentence in the next specification version.
- `c18-rust-r2` shows that the check cannot help an agent that does not
  reach a buildable state; whether a 45-minute first round is too long for
  "keep it building" is a design question, not a defect.
