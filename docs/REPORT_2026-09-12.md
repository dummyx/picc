# PiCC report, 2026-09-11/12: the hang hazard, the v6 and v7 batches, and what comes next

Prepared for the project owner at the end of the 2026-09-11 session. Every
claim below is backed by committed artifacts on branch
`fix-experiment-validity`; pointers are given per section. Nothing has been
merged to `main`.

## 1. In one paragraph

The variance that had swamped every contrast since v2 was a harness hazard,
not the model or the conditions: Pi's shell tool has no default timeout, so
an agent that ran a program its own half-built compiler had miscompiled into
an infinite loop blocked its session until the round cap. Bounding shell
commands (a pinned community package that gives the bash tool a 120 s
default) removed it completely: in the new v6 batch all eight runs used
their full budget and the spread of the corpus score fell from 0.50 to 0.08.
Under that clean harness, withholding tests from the agent does not
detectably change correctness (paired median −0.017 on the corpus, 0.000 on
the fuzzer, n=4); it changes process (about 100 more turns and 500 more
lines of compiler in the same time). A second audit-scope defect surfaced
and was handled by a pre-declared amendment. The next batch re-tested the project's
original question (static typing) on the clean harness and found the same:
no effect on correctness, a large effect on how the work is done.

### 2.2 The bash default timeout (commits d43a1ca, 7218e06)

- **Evidence.** Session timestamps of the 20 v3–v5 main runs: 2670
  completed bash calls, p99 = 5.1 s, longest legitimate 40 s; 18 calls that
  never returned, in 14 of 20 runs, median 34 minutes lost each, 8.9 of 40
  budget hours in total.
- **Upstream position, checked properly.** Pi ships no default and has no
  setting for one; the maintainer declined it in April ("tell the agent to
  set a timeout that makes sense"), and later requests and a PR were closed
  unmerged. Customization is the intended route.
- **Implementation.** First as a guard-extension hook (commit d43a1ca), then,
  at your instruction, replaced by the community package
  `@cad0p/pi-bash-timeout@0.1.0` (MIT), pinned in image
  `picc-experiment:0.4` and loaded from the frozen settings. It re-registers
  the bash tool with a 120 s default; an explicit agent timeout always wins.
  The guard only logs each cut-off. Verified by a mocked-API test, a strict
  type-check, a real Pi session in which a non-terminating self-test was cut
  at exactly 120 s, and a pilot run in which the timeout caught a real hang
  ("t8 hangs — infinite loop. Let me inspect the emitted assembly").
- **Residual.** A model that asks for a long timeout itself still gets it.

### 2.3 Beyond the tests: tokens, time, code shape (commit 4703d83; report §11)

`analysis/dimensions.py` tabulates all 35 main runs of v2–v5. Findings:
96–99.6% of generated characters are thinking; every process variable that
tracked correctness (tokens, minutes, turns, tool calls, at about +0.55)
collapses to noise among the 17 runs that never hung, all of which reach a
fuzz macro of at least 0.953; code shape predicts the corpus score but not
fuzz correctness; the null contrasts had a resource side (specification
conditions +50–90% tokens, TypeScript +54% lines, withholding tests
−35–45% tokens, all for equal fuzz correctness).

### 2.4 The v6 batch (commits 32f428a … 90904b9; report §12)

Planned in advance before the first run, with two amendments logged during and
after the batch (`docs/EXPERIMENT_PLAN_v6.md`). Eight runs, `tests-none`
vs `baseline`, 4 replicates, image 0.4, same budget as v5.

| | v5 | v6 |
|---|---|---|
| runs idling ≥ 5 min | 5 of 8 | 0 of 8 |
| commands cut by the default timeout | — | 3 |
| corpus range | 0.476–0.974 | 0.897–0.975 |
| fuzz macro below 0.9 | 3 of 8 | 1 of 8 |

Primary contrast, `tests-none` − `baseline`, paired by replicate:

| Endpoint | Paired deltas (r1–r4) | Median | Beyond ±0.13 |
|---|---|---:|---|
| Corpus (hidden macro) | −0.008, −0.026, −0.064, −0.007 | −0.017 | 0 of 4 |
| Fuzz macro | 0, 0, 0, −0.244 | 0.000 | 1 of 4 |

No detectable effect on either endpoint. Two baseline runs reached the
completion threshold; no `tests-none` run did (best 0.924). What withholding
tests changes is process: about 100 more turns and tool calls in the same
88 active minutes, 13–24 `test_visible` calls replaced by self-written test
scripts, about 500 more lines of compiler. Token cost is within noise; the
v3 observation of 45% fewer tokens did not survive.

### 2.5 A second audit incident (Amendment 2; commit 32a6e81)

One `tests-none` run's final snapshot scored 0 on both oracles because the
evaluator's blocking audit scanned every Rust file in the workspace and
flagged a differential fuzzer the agent had written under `tests/`, which
the build never compiles; the compiler itself was clean. This is the same
defect fixed for Node after v4 and left in place for Rust, and two protocol
documents still described the workspace-wide scan as intended. Handling was
declared before the corrected score was known: every final snapshot was
re-scored with the audit scoped to `src/`; seven of eight reproduced their
frozen values exactly and the affected run became 0.911 / 1.000. Had the
frozen values stood, the fuzz endpoint would have read "unresolved" purely
by artifact. The fix, its tests, and corrected documents are committed.

## 3. Decision and next step

You delegated the next step. I chose to re-test the project's original
question, static typing, on the harness that is now known to be clean:
batch **v7**, `ts-strict` vs `js-untyped`, 4 replicates, image 0.4, manifest
`picc-types-v2`, planned in advance in `docs/EXPERIMENT_PLAN_v7.md`. Reasons:
v4's null was measured with two hangs and the preprocessing artifact in
play; the resource cost of typing (+54% lines, +9% tokens for equal
correctness) becomes a clean secondary result; and it needs no new harness
code. Both candidate pilots passed on image 0.4 before the freeze.

**Outcome (2026-09-12 09:28 UTC; report §13, `analysis/v7-results.md`,
`analysis/typing-metrics-v7.md`).** Eight runs, no hangs (max idle 1.6 min),
five timeout cut-offs, all recovered. Treatment delivered: typed agents ran
`tsc` 21–27 times with no `any` and no suppressions; untyped agents never
tried it. Paired `ts-strict` − `js-untyped`: **+0.004** on the corpus and
**+0.001** on the fuzzer (one replicate beyond the threshold in each
direction). The six runs whose final snapshot builds sit between 0.954 and
0.968 on the corpus, the two arms interleaved; three of four runs per arm
reached the completion threshold. So the original question has its answer
on a clean harness: static typing does not detectably change correctness
here. It does change the work: about 40% more compiler source, an order of
magnitude more self-written tests (median 128 programs vs 9), two dozen
type-checker runs, slightly fewer turns, the same time and tokens within
noise.

**The new hazard.** With hangs gone, the largest differences come from the
45-minute round cap landing mid-refactor: once per arm, the final snapshot
was a half-finished rewrite. The type gate scores that 0; `node --check`
lets a runtime-broken program through to a corpus 0.50. Both were
pre-declared outcomes and cancel in this batch, but two of eight finals is
the same order of loss the hangs used to cause. Fixing it is an
endpoint/protocol decision for the next experiment plan (a "last buildable
snapshot" co-primary, or a wrap-up signal before the cap), not a harness
patch to apply retroactively.

The alternative I did not pick, a forced-test-feedback condition, needs new
harness code and a pilot cycle; it is the natural batch after v7.
