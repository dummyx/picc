# PiCC report, 2026-10-05: v18 (stopped), v19, and what v20 changes

For the project owner. Twenty-five two-hour runs on the two newer tasks,
2026-10-02 to 10-04: the six SQL runs of v18 before it was stopped, and the
nineteen runs of v19 (SQL engine and chapters 1-18 compiler; Rust, Python and
typed Python, three each, plus one Rust run with a minimal specification).
Scores are from `analysis/v18_results.py` and `analysis/v19_results.py` over
the study summaries; causes of the zeros were read from each run's own
records (the saved conversation, the scorer's record for every test, the
files the agent left behind).

## 1. Summary

- **The harness held in every run**: 25 of 25 used their full two hours, no
  reply was lost to a server error, no conversation summary failed.
- **v18 was stopped after six runs** because three of them scored 0 (or
  0.069) for mistakes in how the program reads and prints, not in what it
  computes: one engine read standard input instead of the named file, one
  printed rows without the required `ok N` line, one printed a value where
  that line goes. The v17 report had named exactly this failure; running the
  same design again could not answer anything.
- **v19 put a worked example, the input rule and the deadline rule into the
  specification and kept it in view all run.** That worked for what it
  named: in nineteen runs, no hidden script was lost to the output format.
  Two runs still scored 0, each for a new reason the specification had not
  stated: a Rust agent built its crate in a subdirectory, so the official
  build command found nothing; a typed-Python agent never ran `mypy`, so the
  official build command (which is `mypy --strict`) failed on a program that
  otherwise worked.
- **Typing: no effect detected.** Among working runs, typed Python minus
  Python, paired by replicate: SQL −0.008, compiler +0.060; both inside the
  ±0.13 line used since v4. Spreads within a language where no run was
  zeroed are 0.05–0.09, as large as any difference between languages.
- **Minimal specification, one reading:** 0.589 against 0.811 for the same
  replicate with the full specification (−0.222). One run is a reading, not
  a measurement; v20 runs three.
- **What v20 changes, and nothing else:** after every round the harness
  already builds the snapshot with the official command and runs it. From
  v20 it also runs the specification's example and tells the agent the
  result — the build failure with its output, or what the program printed
  next to what is required, or that both passed — instead of the bare
  `Continue.`. Run on the six zero workspaces above, that message names each
  problem after the first round. v20 is the same 18 runs plus three
  minimal-specification runs.

## 7. What v20 changes

One thing. The round message after the first is no longer `Continue.`; it is
the harness's check of the snapshot the agent just left, then `Continue.`:

- the official build command failed → the command, and its output (for typed
  Python, the `mypy` errors);
- built, but the specification's example gives a different output → what the
  program printed, what is required, and the first line where they differ
  (compiler: what each of the two example programs did);
- both pass → one line saying so.

The check uses only what the specification already states (its build and
entry commands, its example); no test, score, hint or round number reaches
the agent through it; the wording is the same for every language and both
tasks. It is switched on by one block in the study manifest and frozen into
each run, so every older study is unchanged. Tested on the mock engines and
mock compilers, and on the six zero workspaces above in the pinned image:
`analysis/v20-check-demo/` holds the six messages. Examples:

- `v19-sql-rust-r3`: *The build command `cargo build --release --offline`,
  run in /workspace, failed: error: could not find `Cargo.toml` in
  `/workspace` or any parent directory*
- `v18-sql-rust-r2`: *… run as `target/release/pisql INPUT.sql` on the
  example input from the specification, the program printed: (nothing) …
  The first difference is on line 1: the program printed nothing, the
  specification requires `ok 0`.*
- `v19-c18-python-typed-r2`: the build command failed, followed by the
  `mypy` error list.

v20 is 21 runs (`docs/EXPERIMENT_PLAN_v20.md`): v19's 18, plus
`rust-minimal-spec` ×3 on the SQL task, with the same check (so the only
difference from `rust` is the specification text; the minimal-spec agent sees
the example's required output only through the check, and only when its own
output differs). About 46 hours.

## 8. Problems in the experiment setup, this round

- v18 ran a design the v17 report had already shown to be noisy for a known
  reason; it should not have been launched as it was. Stopped after six runs.
- v19's Amendment 1 (where the commands run) was found by a zero, as v18's
  defects were; the sentence was added mid-batch (runs 1–6 had all placed
  their files at the root, so the sentence could not have changed them;
  `rust-r3` is reported as 0 with its cause). Reading the two amendments
  together is what led to v20's design instead of a third sentence.
- Between v19's end (20:15Z) and v20's start (22:04Z) the machine sat idle
  for 1 h 49 min: the manifest change v20 needed was waiting on me, and my
  session was unavailable in that window. The launcher refused to start
  rather than run the wrong manifests, which is the behaviour it was written
  for.

## 9. What this does and does not show

- Shows: the harness is stable (25 of 25 runs clean); the example in the
  specification fixes the output-format zeros; the remaining zeros are the
  agent never seeing the official check; typed Python and Python are within
  each other's spread on both tasks at n = 3.
- Does not show: an effect of typing in either direction; an effect of the
  specification's length (one reading); anything about the languages beyond
  three replicates with one zero in two of the six cells.
