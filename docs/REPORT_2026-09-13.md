## 1. In one paragraph

Step 1 is done: the snapshot rule was fixed by experiment plan (both oracles
scored on the last buildable snapshot), the pushed-test-feedback condition

## 2. Step 1: the pushed-feedback batch

### 2.1 What was built (commit f87d762)

- **`tests.push_interval_minutes`**: a manifest key; when set, the tools
  extension's `turn_end` hook runs the full visible evaluation about every
  N minutes at a turn boundary and queues the same failure-level report the
  tool returns as a user message before the next model call. The agent's
  guidance announces it. Logged and counted per run.
- **Last buildable snapshot**: the post-hoc evaluator fuzzes the last
  snapshot that built and passed the audit as a second ledger row whenever
  the final one did not build; the summarizer verifies both rows and adds
  `hidden_score_last_buildable` / `fuzz_macro_last_buildable` with paired
  deltas. Older ledgers get a warning, not exclusion.
- 163 unit tests; both pilots passed on image 0.4 (the pushed pilot
  delivered two reports and the agent acted on each).

### 2.2 The batch (experiment plan 93260e6, report §14)

`baseline` vs `tests-pushed`, 4 replicates, image 0.4, same budget and
model as v6/v7. Eight runs, 13:26 UTC on 12 Sept to 01:30 UTC on 13 Sept.

| | Result |
|---|---|
| Hangs | none (max idle 0.7 min); 2 timeout cut-offs recovered |
| Pushed reports | exactly 8 per treated run, on schedule |
| Corpus, last buildable, paired median | −0.025 (0 of 4 beyond ±0.13) |
| Fuzz, last buildable, paired median | −0.002 (0 of 4 beyond ±0.13) |
| Finals cut by the cap | 1 (pushed r4: 0/0 final, 0.894/0.932 last buildable) |

Per arm: baseline 0.956 median corpus (sd 0.015), fuzz 1.000; pushed 0.942
(sd 0.026), fuzz 0.998. What pushing changes: on-demand calls 16 → 10.5,
turns +26, self-written test programs 0 → 107 (median), self-test lines
+742, tokens and time unchanged. The agents reconstruct the failing cases
the report names but does not show.

### 2.3 The snapshot rule in action

`tests-pushed` r4 was mid-refactor when the cap fell; under the old rule
that replicate would have read −0.950 / −1.000 and the fuzz endpoint would
have shown a replicate beyond the threshold. Under the planned in advance rule
it scores its round-0 snapshot and the contrast reads like the others. Its
own pushed reports show a 0.98 compiler two minutes before the cut, which is
the remaining cost of round-end snapshots.

## 4. Where this leaves the project

**Answered, on a clean harness, with the noise the earlier batches lacked:**
for this model on this task, prompts, specification detail, test access,
test feedback, and static typing do not change the compiler; they change
turns, tokens, code size, and self-testing. The model saturates stages 1–10
in 90 active minutes.

**If you want conditions to separate on correctness**, the lever is the
task, not the factor: stages beyond 10 (the upstream suite has twenty), or a
budget short enough that saturation does not occur. Either can reuse every
factor and harness piece as they stand.

**If you want to publish what exists**, the report is the document, the
experiment plans are the audit trail, and `analysis/dimensions.py` and the
per-batch result scripts regenerate every table from the raw ledgers.
