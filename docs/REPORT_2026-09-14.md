# PiCC report, 2026-09-14: v9, specification detail × test access

Prepared for the project owner after "begin to complete the comparison".
Continues `docs/REPORT_2026-09-13.md`. Every claim is backed by committed
artifacts; pointers per section.

## 1. In one paragraph

The 2×2 cohort ran: full or minimal specification, with or without tests,
three runs per cell, twelve runs, 01:35–19:42 JST. The minimal
specification (143 words, no behavioral rules, no mention of the book)
does not detectably change correctness on either oracle: −0.070 on the
corpus with tests, +0.046 without; −0.020 and +0.200 on the fuzz oracle.
What it costs is the test suite's rejection conventions (6–11 invalid
programs accepted per run against 2–4) and what it changes is size (60–80%
more compiler, features nobody asked for). Withholding tests under the full
specification is the first tests contrast in five cohorts with a mechanism:
two of three agents replaced the system assembler with a self-written
simulator and shipped compilers whose output does not assemble (fuzz 0.80
and 0.20). Paired median −0.200 on the fuzz oracle, two of three replicates
beyond the threshold: unresolved by the pre-registered rule, a candidate
effect warranting replication. Two scoring defects surfaced during the
cohort and were handled by amendments declared before the corrected numbers
existed; the fixes and a full re-score followed after the last run, with
nine of twelve runs reproducing exactly.

## 4. Two amendments (`09f261d`, `2ff1245`) and the re-score (`198bbb0`)

1. An advisory audit note (the compiler reads a debug environment variable)
   disqualified a buildable snapshot from the last-buildable rule; the run
   would have read 0 / 0 instead of 0.784 / 0.727.
2. The dependency audit scanned every Cargo manifest in the workspace and
   zeroed a compiler for its developer crate's path dependency on itself;
   corrected 0.869 / 0.800.

Both rules were declared before the corrected numbers were known; nothing
was changed while the cohort ran; the fixes carry unit tests (174 pass);
the re-score of all twelve runs from scratch copies reproduced nine exactly,
changed the two amended runs as declared, and moved one unaffected run by
0.001 (one of 1000 fuzz programs is nondeterministic in that candidate; the
frozen value is kept). Frozen ledgers are untouched; corrected ones are in
`analysis/v9-rescore/`. One operational slip: the re-score driver's scratch
copy carried a symlink back to the real runs directory, so the corrected
ledgers were briefly written over the frozen ones; they were restored from
the backup taken before the re-score and verified byte-identical. The
re-score procedure, including the symlink replacement, is now written into
`docs/STUDY_PROTOCOL.md` under "Re-scoring after an amendment".

## 5. What it means

- **The specification factor is closed on this task.** The C language is
  the specification and the model knows it; the written document
  contributes only the suite's rejection conventions. No wording of a C
  specification can test whether specifications matter. The next task must
  carry rules the model cannot recall.
- **Tests matter where the agent cannot be its own oracle.** The agent
  reconstructs C semantics from knowledge and tests them itself; it cannot
  reconstruct assembler syntax, and when it stops checking against the real
  assembler, the compiler fails in the real world while passing its own
  tests. This is a mechanism, replicable by design: a `tests-none` cohort
  with more replicates and assembler use as a pre-declared mediator.
- **Less specification, more empirical checking.** Every minimal-spec
  agent went to the assembler; two of three full-spec, no-tests agents did
  not. The detailed specification let the agent believe it knew the target.
